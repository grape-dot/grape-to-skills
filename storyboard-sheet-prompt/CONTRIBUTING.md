# Contributing

感谢愿意花时间。这个项目的重心是**一致性约束**，所以改动请围绕它来评估。

## 最有价值的贡献

1. **真实出图对比。** 目前「单页九格在 2K / 4K 下会不会糊」只是判断，没有实测。跑 A（单张整页）与 B（分区生成再拼），把结果、分辨率、模型版本记进 `evals/` 下的新文件，就能把这条假设变成数据。
2. **新的 Bible 范例。** 群像（3 个以上角色）、跨地点、夜戏各缺一份 `examples/*.json`。照 `examples/nut-crisis.json` 的结构写，跑通再提 PR。
3. **九拍节奏预设。** 目前只有默认一套（闹剧型）。悬疑、温情两种的镜别序列可以写成 `references/sheet-layout.md` 的新小节。

## 提 PR 前

```bash
python -m unittest discover -s tests -v
python scripts/assemble.py examples/nut-crisis.json --stdout > /dev/null
```

两条都要过。

## 改动规则

- **改了校验逻辑，必须补测试。** 加一条"证明新规则能拦住坏输入"的用例。校验测试是 `assemble.py` 存在的理由，没有测试的校验等于没有校验。
- **不要 weaken 硬前提。** `SKILL.md` 的四条硬前提和 13 条红线是行为契约，不是建议。要改，先在 issue 里说清为什么现在的约束碍事。
- **提示词里不许出现 `prop_id` 或 `key=value`。** 出图模型会把这些当作画面文字画出来。`test_no_prop_id_leaks_into_prompt` 会拦。
- **保持零依赖。** 脚本只用标准库。加依赖要先在 issue 里论证收益。
- **中文文档与英文文档同步。** 两者不是互译，但章节结构要保持一致，避免一份有、一份没有。

## 代码风格

- 注释只写"为什么"，不复述代码；不留 TODO 便签。
- 新增输出模板时，槽位用 `{}`，其余骨架原样保留——骨架就是防漂移的部分。
- 报错信息用中文，带位置（`shot 04`、字段名），一次报全所有错误再退出。

## 提交信息

```
<类型>: <一句话>

类型: feat / fix / docs / test / chore
示例: fix: 面板行不再泄漏 prop id，避免被画成画面文字
```
