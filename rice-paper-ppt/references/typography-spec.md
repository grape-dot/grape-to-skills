# 全局视觉排版与字号规范（原文存档）

> 这份文档是这套版式的**验收标准**。做页面、改页面、复查页面时都以它为准；
> 与「好看」冲突时，以它为准。原文照录，未做删改。
>
> 原文写作时以「课件」为目标文件、以「教学」为场景，属于通用表述的举例；
> 用于汇报、路演、分享等场合时，把「课件」读作「幻灯片」、「教学正文」读作「核心正文」即可，
> 字号与空间标准完全一致。

## 01｜任务目标

你是一名资深 PPT 视觉设计师、信息设计师和前端开发工程师。

请对当前 HTML PPT 及其关联的 `theme.css` 进行全局视觉优化和逐页排版重构。

当前课件主要存在以下问题：

- 正文字号偏小，不适合教室大屏幕投影。
- 页面空间利用率不足，存在大量无意义的留白。
- 部分卡片内部文字较少，但卡片占用空间过大。
- 标题、正文、注释之间的视觉层级不够明显。
- 图片、视频、图表的展示面积偏小。
- 部分页面更像网页文章，而不是专业教学 PPT。
- 页面内容分布不均衡，存在局部拥挤、局部空旷的问题。

本次优化的核心目标：

**让字体更大、内容更集中、主体更突出、排版更饱满，同时保持专业感、秩序感和阅读舒适度。**

## 02｜整体设计原则

保留原有课件的设计语言，包括米白色背景、墨绿色主色、哑光金辅助色、字体风格及整体视觉识别体系。

不重新设计品牌风格，重点优化信息呈现方式。

整体排版应满足：

- 大字号、高可读性。
- 中高信息密度，避免过度极简。
- 清晰的信息层级与视觉阅读顺序。
- 图文结合，而不是大量小字号文字堆叠。
- 页面视觉饱满，但不拥挤。
- 适合课堂教学、会议室大屏和全屏演示。
- 每一页具有明确的视觉中心。
- 不采用千篇一律的卡片网格布局。

将“适度留白”理解为帮助信息分组，而不是单纯减少页面内容或制造大面积空白。

## 03｜页面尺寸与空间利用率

统一使用 16:9 横版幻灯片。

以 1280 × 720 px 为设计基准尺寸，若原项目采用其他尺寸，则按比例换算以下规范。

建议空间参数：

| 设计项目 | 建议规格 |
|---|---|
| 页面左右安全边距 | 40–48px |
| 页面顶部边距 | 28–36px |
| 页面底部边距 | 24–30px |
| 一级模块间距 | 20–28px |
| 普通组件间距 | 12–20px |
| 卡片内部边距 | 16–22px |
| 标题与正文间距 | 16–24px |
| 图文间距 | 20–28px |
| 内容区域宽度利用率 | 90%–94% |

普通内容页的主要内容区域应充分利用标题与页脚之间的空间，建议视觉内容覆盖可用区域的 80%–90%。

封面、章节分隔页不强制执行内容覆盖率要求。

禁止出现：

- 页面下半部分大面积空白。
- 页面中间存在无意义的空白断层。
- 内容全部集中在页面上半部分。
- 为了追求高级感而过度扩大页面边距。
- 卡片尺寸很大，但内部只有几行小字。
- 内容区存在明显未被利用的角落。

## 04｜全局字号体系（重点）

建立统一的 Typography Design Tokens，集中管理全局字号。

以下字号均基于 1280 × 720 px 的设计画布。

| 文字层级 | 推荐字号 | 字重 |
|---|---:|---:|
| 封面主标题 | 64–80px | 700–800 |
| 封面副标题 | 32–42px | 600 |
| 章节分隔标题 | 56–68px | 700 |
| 页面主标题 | 36–44px | 700 |
| 页面引导语 | 22–26px | 400–500 |
| 一级模块标题 | 26–30px | 600–700 |
| 卡片标题 | 22–26px | 600–700 |
| 正文内容 | 20–24px | 400–500 |
| 表格表头 | 20–22px | 600–700 |
| 表格正文 | 18–22px | 400–500 |
| 提示词正文 | 19–22px | 400–500 |
| 代码内容 | 18–20px | 400–500 |
| 图表标签 | 17–20px | 500 |
| 图片说明 | 15–17px | 400 |
| 辅助标签 | 14–16px | 500 |
| 页脚与页码 | 13–15px | 400 |

强制要求：

1. 核心教学正文原则上不得低于 20px。
2. 高密度表格、代码和提示词内容原则上不得低于 18px。
3. 除页脚、图注及非核心元数据外，不允许使用低于 16px 的字号。
4. 不允许为了把内容塞进一页而不断缩小字体。
5. 内容过多时，优先精简文案、调整结构或拆分页面。
6. 中英文混排时，保证视觉字号协调。
7. 重点内容通过加粗、色彩、位置和字号突出，而不是全部加粗。

正文行高建议为 1.45–1.65，标题行高为 1.15–1.3。

## 05｜信息密度与视觉层级

每页建立三个清晰的信息层级：

- 第一层：页面标题、核心结论、主要视觉焦点。
- 第二层：关键知识点、案例、流程、图片、表格。
- 第三层：补充说明、参数、注释与来源。

保证学生能够在短时间内识别页面主题，并快速定位核心知识。

对大段文字进行结构化处理：

- 将连续段落转化为关键词与解释。
- 将操作过程转化为流程图。
- 将差异性内容转化为对比布局。
- 将参数与配置转化为表格。
- 将技术关系转化为架构图。
- 将案例过程转化为前后对照或阶段展示。

不要为了提高信息密度而增加无意义的内容。

## 06｜不同页面类型的排版规范

### A. 理论知识页

采用大标题、核心结论、主体图示与补充说明的结构。

优先使用左右分栏、上下分区或主次布局，避免所有知识点都使用等宽卡片。

核心知识点必须具有足够大的字号和视觉权重。

### B. 图文案例页

图片或视频应占据页面内容区域的 45%–65%。

优先放大案例本身，再安排文字说明。

禁止在左侧放置一张很小的图片，右侧堆积大量小字号文字。

图片应保持合理比例，不拉伸、不变形、不裁掉重要主体。

### C. 提示词展示页

重点展示提示词内容本身。

采用「提示词原文 + 生成结果 + 关键约束标注」的布局。

- 提示词字号不低于 19px。
- 使用色彩或背景高亮本次新增的约束。
- 保持段落结构清晰。
- 减少不必要的装饰边框。
- 长提示词可以拆成结构化段落或独立页面。

### D. 视频演示页

将视频播放器作为页面主要视觉主体。

在条件允许时，视频展示宽度建议达到页面宽度的 50%–65%。

双视频对比页采用等宽并列布局，保持相同的展示尺寸和对齐方式。

保留原有播放控制、声音开关和交互功能。

### E. 流程图与技术架构页

扩大流程节点、连接线、标题和关键技术标签。

流程图应充分利用横向空间。

避免出现流程图面积很小，而页面其余区域大量空白的情况。

节点内部文字必须清晰可读，技术关系必须准确。

通过颜色、线条、模块分组表达层级关系，不依赖复杂装饰。

### F. 表格与对比页

- 表格充分利用页面横向空间。
- 根据内容长度合理分配列宽。
- 表格行高建议为 38–50px。
- 强化表头、核心字段与重点结论。
- 避免过细、过密的表格线。
- 表格内容过多时进行分组或拆页。

### G. 卡片与模块页

减少机械化、等宽、等高的卡片布局。

根据内容的重要程度决定卡片尺寸，形成主次关系。

避免为了保持卡片等高而产生大量内部空白。

通过浅色背景、细边框、轻微阴影和局部强调色建立层次，不使用过度装饰的厚重边框。

### H. 章节分隔页

允许适当增加留白，但不能只有一个小标题漂浮在页面中央。

采用大字号章节编号、大标题、核心引导语和必要的章节学习目标。

形成明显的课程节奏与视觉过渡。

## 07｜重点解决页面空旷问题

逐页检查页面空间使用情况，并采用以下优化策略：

1. 放大标题、正文、图片、视频及关键图示。
2. 缩减不合理的容器固定高度和过大的 padding。
3. 减少不必要的 margin、gap 和空白占位元素。
4. 将过小的模块重新组合为主次分明的信息区域。
5. 根据内容数量调整 Grid 和 Flex 布局比例。
6. 重新分配标题区、内容区和底部总结区的高度。
7. 对内容较少的页面，优先放大主体和增强信息表达，而不是强行添加文字。
8. 对内容较多的页面，优先调整结构，而不是缩小字体。

特别检查 `justify-content: space-between`、`justify-content: space-evenly`、`margin-top: auto`、固定高度以及多层嵌套容器是否造成不合理的空间分布。

不要机械删除这些属性，应根据每页实际布局决定是否保留。

## 08｜视觉丰富性与版式变化

根据页面内容灵活使用以下版式：

- 左文右图。
- 左图右文。
- 双案例横向对比。
- 主视觉与辅助说明。
- 横向流程图。
- 纵向递进结构。
- 技术分层架构。
- 非对称网格。
- 全宽案例展示。
- 上方核心内容、下方结论总结。

相邻页面不应持续采用完全相同的排版方式。

保持设计体系一致，但允许页面结构根据教学内容发生变化。

## 09｜HTML 与 CSS 实施要求

首先分析现有 HTML 结构、`theme.css`、公共组件及页面内联样式。

重点检查 `.slide`、`.sh`、`.sb`、`.stitle`、`.lead`、`.card`、`.ct`、`.cb`、`.tbl`、`.pbox`、`.pt`、`.note`、`.foot` 等现有样式。

实施要求：

- 建立统一的 CSS 字号变量、间距变量和颜色变量。
- 优先修改公共样式，保证整套课件视觉一致。
- 检查并清理与全局规范冲突的内联字号。
- 对特殊页面进行独立布局优化。
- 保留原有图片、视频、SVG、代码和素材引用路径。
- 保留翻页、键盘控制、全屏播放、视频播放等交互逻辑。
- 保持浏览器缩放、全屏演示和打印模式的正常运行。
- 不引入不必要的第三方依赖。

严禁使用以下方式掩盖排版问题：

- 通过 `transform: scale()` 单独缩小内容。
- 通过 `zoom` 强行压缩页面。
- 通过 `overflow: hidden` 隐藏溢出的有效内容。
- 通过负边距强行挤压元素。
- 通过持续减小字号解决内容溢出。
- 通过滚动条展示幻灯片中无法容纳的正文。

允许保留整张幻灯片适配浏览器窗口所需的等比例缩放机制。

## 10｜逐页渲染与视觉验收

修改完成后，使用 Playwright 等浏览器自动化工具，对所有幻灯片进行逐页渲染截图和实际视觉检查。

不能只检查 HTML 代码或 CSS 参数，必须以真实渲染结果作为验收依据。

逐页检查：

- [ ] 核心正文达到规定字号。
- [ ] 页面没有不合理的大面积留白。
- [ ] 标题与正文层级清晰。
- [ ] 图片、视频及图表足够大。
- [ ] 所有内容完整显示。
- [ ] 不存在文字溢出、遮挡、裁切或重叠。
- [ ] 卡片内部空间分配合理。
- [ ] 页面元素对齐统一。
- [ ] 原有交互功能正常。
- [ ] 全屏投影状态下具有良好的可读性。
- [ ] 不同页面保持统一设计体系。
- [ ] 页面内容饱满，但没有明显拥挤感。
- [ ] 页码统一为「当前页 / 总页」，末位等于总页数，当前位等于物理页序（封面、章节页、结语都在编号内）。
- [ ] 每个模块首页是深绿章板且带本章徽记，和相邻正文页一眼能分开；徽记不压右上编号、不压右下格言。
- [ ] 每段视频都能暂停、有进度条、能拖动跳转，时间码随播放变化。

发现问题后直接修改并重新渲染，直到通过验收。

## 11｜最终执行要求

直接在现有 HTML PPT 项目基础上完成重构，不要仅提供修改建议或示例代码。

保留原有课程知识体系、核心教学内容、案例素材及技术逻辑，不随意删除关键知识。

允许根据实际排版需求调整页面数量、重新划分内容区域和优化重复文案。

优先级从高到低：

**内容正确性 > 投影可读性 > 信息层级 > 空间利用率 > 视觉美观 > 装饰效果。**

最终呈现应是一套字号充足、信息密度适中偏高、视觉饱满、图文比例合理、具有专业教学品质的 HTML PPT，而不是网页文章、产品介绍网页或过度留白的极简演示文稿。

核心设计要求：

**大而不乱，满而不挤，密而有序，重点突出。**
