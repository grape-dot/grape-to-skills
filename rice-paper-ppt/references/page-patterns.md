# 版式配方（按页面类型选）

先判断这页的页面作用，再选版式。**不要所有页都用卡片网格**——那是“模板感”和“空”的共同来源。

内容区高度固定 512px（`.sb` 从 150 到 662）。下面每个配方都按 512px 估算，
最后一栏写“这页最容易踩的坑”。

## 1. 封面

- 结构：右侧视觉（配图或渐变）+ 左侧标题块 + 底部 4 个特性。
- 标题 76px、副标 32–42px；特性块 14px 标签 + 15px 描述。
- 坑：4 个特性是最多的数量，第 5 个会掉到下一行压住页脚。

## 2. 章节分隔页

- 底色：`<section class="slide plate">`，深绿渐变 + 金色左竖条 + 右上角米色幽灵编号。
  **底色不加重，翻页时就没有“换章”的感觉**——只换标题是不够的。
- 章板上配色整套换掉：标题米白 `#F4ECDA`、引导 `#BFC9B9`、金标 `#C8A96A`、页脚 `#8FA08A`、
  编号 `rgba(233,223,196,.11)`。这些 `.plate` 规则已在 `theme.css` 里写好，加个 class 就生效。
- 结构：超大编号（224px，右上出血）+ 大标题（60px）+ 一句引导 + 3 条学习目标 + 一句格言（右下）+ **本章徽记**（右侧空白处）。
- 徽记排位固定：`right:92px; top:268px; width:300px`；环 184px、图标 96×96、金线 26×1、小标 12.5px。
  上面让开 `.sec-num`（占到 y≈250），下面让开 `.sec-mark`（`bottom:78px`）。
- 坑：`.sec-num` 用 `right` 负值出血时，不要同时给它 `opacity` 之外的滤镜，打印会掉。
- 坑：图标别超过 104px，环内 9px 处的虚线内圈会被顶穿。
- 坑：深底上别再抄正文页的墨绿字，`#2F4A38` 在章板上等于隐形。图标一律 `currentColor`。
- 三条要点**必须自带名词**：写「Remotion 链 / 手拼链」，不要写「一条链 / 另一条链」。
  章节页是学生翻到这一章唯一会看的一屏，靠正文上文才懂的指代（这个、那个、另一条）在这里等于没说。
  加粗只给命名的那两三个字（`.plate .sec-pts li b` 会提亮到米白），别整句加粗。

### 2b. 徽记图标库（复制即用）

外壳固定，只换 `<svg>` 里的图形与 `.em-lb` 的小标：

```html
<div class="sec-emblem">
  <div class="ring">
    <svg viewBox="0 0 120 120" fill="none" stroke="currentColor" stroke-width="2.4"
         stroke-linecap="round" stroke-linejoin="round">
      <!-- 下面七个片段任选其一 -->
    </svg>
  </div>
  <div class="em-rule"></div>
  <div class="em-lb">CHAPTER 01</div>
</div>
```

主线条一律 `stroke="currentColor"`（实心件用 `fill="currentColor"`），由 `.sec-emblem` 的 `color` 决定：
米纸页是墨绿，章板上自动变米白。金色小件写死 `#A87F3F` 即可——`.plate` 里有规则把它提亮到 `#CDA96A`。
SVG 的 presentation attribute 不吃 `var()`，所以别在图标里写 `var(--green)`。

## 3. 图文案例页（最常用）

- 结构：`grid-template-columns: 1fr 1fr`（或 `1.2fr 1fr`），左图右文 / 左文右图交替。
- 图占 45%–65%。做法：容器定高（约 410–450px）+ `object-fit:contain`。
- 右侧若是 3 条结论：`.card` 包一层，卡内 `.cb` 每条 ≤ 2 行。
- 坑：图片高度只能从“内容区剩余高度”里算，先扣掉 `lead`（37px）和图注（约 46px）。

## 4. 双案例对比页

- 结构：两列等宽，各含“视频/图 + 单行说明”，底部一条 `.bar` 收束。
- 两列的标题**不要各写一行**，会多出 44px；把标题并进图内 `.vl` 或统一放页眉。
- 坑：双视频页最容易溢出 40px 以上，因为两个 `<video>` 的 `poster` 比例不一致。

## 5. 表格页

- 结构：`lead` → `.tbl rows`（4–7 行）→ 一条 `.bar`。
- 7 行以上改 `.tight`；10 行以上考虑拆页或改 `.xs` + 精简列。
- 列宽：第一列给 `width:96–150px`，中间列给具体值 `210–260px`，最后一列吃剩余。
- 坑：`padding` 一加就超，`.tight` 的 7px 是实测上限。

## 6. 提示词页

- 结构：`pbox`（左，占 55–65%）+ 生成结果图/视频（右）+ 一条“这次新增了什么”的 `.bar`。
- `.pt` 20px / 行高 1.85 是投影下限；4–6 行最舒服，超过 8 行必须有高亮或拆页。
- 坑：`pbox` 被 grid 拉伸后，内容只占上半截 → 加 `align-self:center` 或 `justify-content:center`。

## 7. 四步/多步流程页

- 结构：`.flow`（4 节点 + 3 箭头）+ 下方 `.g3` 三条旁注 + 一条 `.bar`。
- 节点内：`.fn` 编号 + `.ft` 标题 + `.fa` 说明 + `.fx`（贴底，用 `margin-top:auto`）。
- 坑：只有 `.flow` 一行的页面必然空 200px 以上——必须补旁注或 `.bar`。

## 8. 术语/参数密集页

- 结构：4 列 × 4 行 `.term`，或 `.tbl.xs`。
- 引导语要压到一行：右侧放参考链接时，`lead` 的 `max-width` 要扣掉链接宽度，否则挤出孤字行。
- 坑：术语 17–18px 是极限，再多一列就不可读。

## 9. 代码页

- 结构：代码块（左，`font 18px / line-height 1.6–1.7`，≤ 14 行）+ 右侧 3 条解释。
- 长注释改行尾注释，不要单独占一行。
- 坑：`.code` 是 `overflow:hidden`，超出的行**不会报错，只会消失**——必须靠 `scrollHeight > clientHeight` 检测。

## 10. 收尾/作业页

- 结构：主题卡（题干）+ 3–4 条要求 `.bar` + 评分表 + 一条总结。
- 用 `g2`（左题右要求）比三张竖卡更省空间、也不空。

## 11. 视频页

- 结构：`.vid`（16:9，`overflow:hidden`）里放 `<video muted loop autoplay playsinline>` + `.snd` 开声音按钮 +
  `.vid-print` 打印兜底图；说明文字用 `.vt`，默认在**左上角**。
- `deck.js` 会给每个 `.vid` 自动挂 `.vctl`：播放/暂停 + 可拖拽进度条 + `0:12 / 1:44` 时间码。
  所以**页面里不写控件**，也不许加原生 `controls`。
- 一页最多两块视频；并排时用 `.g2`，每块宽度 ≥ 480px，窄了时间码会挤成一坨。
- 打印态会自动隐藏视频、显示 `.vid-print`，所以**每段视频都要配 poster + 同名首帧图**。
- 坑：往 `.vid` 里再加 `bottom:10px` 的浮层，会和进度条叠在一起；底部整条留给控件。
- 坑：本地用 `python -m http.server` 验收时进度条拖不动——它不支持 Range 请求，浏览器没法 seek。
  换 `file://` 直开、或用一个支持 `Accept-Ranges` 的静态服务再验。

## 12. 多图排版页（图片墙十一式）

一页要并置 4 张以上同题材图片时，不要给每张图各配一张卡片——卡片一多，页面就退回九宫格模板。
做法是**先定几何母题，再把整组从纸面上抬起来**：

> **立体只看四件事：暖白拼缝、沿轮廓的柔和投影、边缘的顶亮底暗、尺寸或位置的错落。**
> 不做发光、玻璃、彩色阴影与内发光——那是科技风的语言，放在米纸上立刻显假。

十一式对应十一类内容关系，选错式比排得不好看更糟。**1–4 式用同一组四张横图各出一张
1280×720 整页实拍（`examples/wall-stagger.jpg` / `wall-wave.jpg` / `wall-depth.jpg` / `wall-fan.jpg`，
标题即式名、标题下即定义），5–11 式各有实拍：`wall-coil.jpg`（整页通栏）、`wall-sec|crest.jpg`、
`wall-grid|fold|arc|arc-inner.jpg`**，下面各式的参数与它们一一对应：

### 1 齐边错落式（照片卡）

> 多张图片独立排列，通过上下错位形成节奏感。


- 结构：`.wall.w-stag` 里放四个 `.pc`。`pc` 是照片卡：`padding:7px` 当白边、底色 `#FFFDF6`、
  高度 300px、双层投影 `0 24px 38px -14px rgba(74,58,34,.50)`；`img` 撑满卡片、`object-fit:cover`。
- 错落靠 `.pc:nth-child(even){margin-top:66px}`：照片同高、正放，只改位置。
  **不要旋转照片**，歪一点就像随手扔在桌上，摆出来的整齐感就没了。
- `.pc::after` 在底部压一条 24px 米白渐变，让照片“坐”进纸面。渐隐必须挂在 `.pc` 上：
  挂在 `img` 上会把投影一起淡掉，悬浮感跟着消失。
- 坑：五张时单张宽度不足 210px，人脸开始难辨，改 3 式；偶数列下移超过 80px 会掉出内容区。

### 2 波浪贯通式

> 多张图片沿连续波浪曲线拼接，形成整体画面。


**四张图，一整条 S，只起伏一次。**做成多个小碎波就成了“波浪边框”，不是飘带。

- 尺寸锁死：`.w-wave` 宽 `calc(100% + 92px)`、`margin-left:-46px` 左右出血铺满画布，
  实宽 1280px，高 400px。`path()` 吃像素坐标，**墙宽一变曲线立刻错位**。
- 曲线自参考图逐列量得，不是手调出来的：**波峰在 20%、波谷在 81%、右端回升到中部偏下**。
  换算到 1280 宽、270 带宽、100 起伏，控制点按 Catmull-Rom 转三次贝塞尔：
  `M0 74 C23 68 91 46 136 39 C181 32 227 31 272 31 C317 31 363 35 408 40 C453 45 499 55 544 63
   C589 71 634 80 679 89 C724 98 770 108 815 114 C860 120 913 124 951 127 C989 130 1012 131 1042 130
   C1072 129 1101 126 1131 121 C1161 116 1198 105 1223 98 C1248 91 1270 81 1280 78
   L1280 348 C1270 351 … 0 344 Z`（完整值见 `theme.css`）。
- **带宽恒定 270px**：上缘到下缘处处 270，只让上下缘一起平移。带宽一变，带子就一头粗一头细。
- 只要 S，不要拱：左端从中部起、先扬到波峰、再一路沉到右下角，末端微回升。
  左右对称的拱门读成“拱桥”，与参考图的飘带感差一层。
- 图间缝 3px，容器底色 `#FFFDF6`：缝要读成白纸，不能是透出背景的透明间隙。
- 投影一律 `filter:drop-shadow()`，不能用 `box-shadow`——`box-shadow` 会被 `clip-path` 一起裁掉，
  页面上什么都不剩；`drop-shadow` 沿裁剪后的轮廓走，波浪边才有厚度。
- `::after` 压一层顶亮底暗（白 50%→14%、暗 34%→18%），补上弯曲受光。
- 坑：起伏超过 130px 会在地脚挖出一个大月牙，图注没处放；`mask-image` 引用外部 SVG，离线打印会丢遮罩。

### 3 纵深渐进式

> 图片按纵向层次递进排列，营造空间纵深感。


**真透视，不是斜切。** `skewX` 只把矩形推成平行四边形，没有近大远小；
要右大左小、向内收，必须 `perspective` + `rotateY`。

- 结构：`.grow` 里两列（文字 30% + `.w-depth-stage`，`gap:20px`），`.w-depth` 绝对定位在 stage 内。
- 摆位：`right: calc(var(--pad-x) * -1)` 让右缘出血、贴住纸边；`top:50%` + `margin-top:-210px` 垂直居中。
  **右缘出血是关键**——一旦完整露出右边，纵深就没法“向内延伸”，只会变成一块漂浮的小板。
- 尺寸：`width:1100px; height:420px;`，`transform-origin:100% 50%`，
  `transform: perspective(1600px) rotateY(-25deg)`。
  这组数对应：右边高 420、左边约 305（比 1.38），可见宽约 760，左缘落在 x≈520。
- 比例怎么调：左右高度比 ≈ `(d + a) / (d - a)`，其中 `a = 墙宽/2 × sin(角度)`。
  想要更陡的纵深就减 `d` 或加角度，但**右缘会被同步放大**（`d/(d-a)` 倍），高度要跟着降，
  否则压到页脚；这是这一式最容易翻车的地方。
- 8 张铺 4×2，缝 3px，容器底色 `#FFFDF6`；`::after` 压顶亮底暗。
- 坑：角度超过 30° 图片内容开始明显拉伸，文字细节读不清；`width` 小于 1000 时可见宽不足 800，
  左缘会掉到文字列上；别用 `rotateY` 但忘了 `perspective` 写在 `transform` 里，那样完全没有纵深。

### 4 不对称叶片式

> 图片以不对称弧形边缘连接，形成叶片般的视觉效果。


**左端最厚、中间最薄、右端回升但不超过左端。** 关键是**一条遮罩裁整墙**，不是五张各改高度。

- 结构：`.wall.w-fan` **四到五张**，`width: calc(100% + 92px)` 左右出血，容器高 400px，`display:flex`，
  `gap:3px`、容器底色 `#FFFDF6`。**图片全部同一高度、不做任何逐张高度**，但取
  `height: calc(100% + 20px)` + `align-self: flex-start`——多出的 20px 只为让左下角越过容器底，
  撑不到布局（`.sb` 仍 512/512）。
- 轮廓：容器上一条 `clip-path: path()`，上缘与下缘各自一条平滑曲线。实测厚度
  **左 393 / 中 231 / 右 283**（参考图逐列量得，换算到 1280 宽 400 高）。
  上缘 13 → 93 → 74（左高右低、末端微回升），下缘 406 → 321 → 357（中段上拱）。
  左端 406 已超出 400 容器：path 可以画到框外，只要图片高度补足、且 `::after` 用
  `bottom:-20px` 跟着延到图片底，明暗不会缺一截。
- 左下角必须单调收束：下缘左段的 y 只能一路增加（贴着画布左缘最厚），中途不许出现
  极小值。早先手写成 `L95 373 C49 376 16 370 0 370`，在 x≈49 处先下探 3px 再回升，
  1280 宽下就是左边缘一个可见的**尖钩**；改成
  `C207 359 130 392 74 398 C40 402 16 404.5 0 406`，两段 y 单调、交界切线一致（C1 连续），
  且末端仍保持向下斜率，读成「被画布切断、还在往下走」，而不是自己收住。
- 为什么必须一条遮罩：逐张改高度会让相邻图之间出现**高度台阶**，五张像堆在一起的卡片；
  同一条 path 裁下去，接缝两侧是同一个轮廓，白缝只出现在带内，整条才连成一片叶子。
- 投影挂容器：`.w-fan { filter: drop-shadow(0 22px 26px …) drop-shadow(0 4px 8px …) }`。
  `drop-shadow` 沿裁剪后的轮廓走，弧形上下缘才有厚度；逐张加 `box-shadow` 会变五张独立卡片。
- 版面：标题在叶片上方（`.wt` 用 `font-size:var(--fs-h1)`、`margin:0` 居中），
  **图注放到叶片下方**、落在下缘那条上拱的凹口里（`.figcap` 加 `margin:0;text-align:center`）。
  标题 40 + 缝隙 + 叶片 400 + 图注 24 正好填满 512 的内容区，不要再给两者加外边距，否则压到页脚。
  左端下探到 406 后会伸进图注那一行的**左侧空白**，所以图注必须居中（`text-align:center`），
  一旦左对齐就会撞上叶片最厚的那一角。
- 坑：等宽是前提，宽窄不一立刻散；path 按 1280×400 写死，改画布宽要重算；
  容器框高 400 是布局预算，形状可以靠 path 越框 + 图片补高多探 20px，
  但再想更厚就得抬 `height`，那时内容区会先撑爆，只能减图数或压标题。
- 坑：**横构图素材进竖格会被裁掉一大半宽**。带内侧一格约 318×420（宽高比 0.76，五张时只有 253×420），
  常见 3:2 横图是 1.5，`cover` 只留下约 **57% 的画面宽度（五张时 45%）**。所以：
  横图配 4，四张比五张安全；按主体逐张给 `object-position`（风景留地平线、月亮/主体靠哪就偏哪），
  别一律 50%。**主体贴画幅边缘时直接推到底**：星月夜的月亮几乎贴着原图右缘，
  格宽 57% 时 50%/62% 都只剩半个圆，要 `100% 50%` 才完整；同一张在 1 格（0.94，留 71%）取 `62%` 能同时留住柏树与月亮。
  规律是「格越窄越要偏向主体」，不是套一个固定百分比。
  要保住整幅构图就别用 4 / 2，改 1 照片卡或图文分栏。
  横图选式有明确顺序：**3 最省**（格 275×210≈1.31，接近 3:2，几乎不裁）→ **1 次之**（283×300，留 67%）
  → **2 / 4 最狠**（320×400 / 318×420，只留 57%）。同一组横图要连排前四式，就该让 3 承担全貌、2 / 4 承担氛围。

### 5 螺旋长卷式（旧称「盘旋丝带」）

**一条带子自上而下绕一圈半，切成七块，每块填一张图。** 前四式都是把图摆开，
这一式是让读者的眼睛跟着带子走进去、再落到右下角。适合「一段历程」——
若干阶段有先后、有回旋、最后收在一处。

5 有两种落位，**同一批 path，只改塔宽与描边**：

| 落位 | 塔 | 缝 | 左列 | 用在 |
|---|---|---|---|---|
| 整页通栏 | 637×720，svg 写 `preserveAspectRatio="none"` 由 CSS 拉满一页高，`right:-30px` 右缘出血、底缘与页底衔接 | 6（显约 10px） | 常规规格：kick 15px + 标题 40px（`.sh`）+ 导语 23px + 图注 + 页脚 | 开篇、换章、收尾 |
| 内容页 | 430×485，`.sb` 里 `align-items:start` | 2.2（显约 2.4px） | 导语 + 标题 40px + 两段正文 + 图注 | 正文中间的案例 |

- 结构（内容页）：`.grow` 两列（文字 `1fr` + 塔 `430px`、`gap:44px`、`align-items:start`），
  左列从 `.lead` 导语开始、到 `.figcap` 收尾，与塔顶齐平。**图注放在左列末尾**——
  留在 `.sb` 里当 flex 项会贴到 `.sb` 底边（实测 503–522），与塔底 462、页脚 533
  三样挤成一堆；挪到 `.sb` 之外又落回普通流、跑到页面顶部。塔是内联
  `<svg class="w-coil" viewBox="-3 -3 386 436">`，`theme.css` 里只给 `width:100%; height:auto`
  和一层 `drop-shadow`。
- 结构（整页通栏）：`<section class="slide">` + `.sh`（kick + stitle）+ `.sb`（`.lead` + `.figcap`，
  **宽限到 520px**）+ `.foot` + `<svg class="w-coil cv-coil" preserveAspectRatio="none">`。
  637 = 720 × 386/426.4 再由 CSS `height:720px` 拉满；`right:-30px` 让右缘出血——形状在 viewBox 右侧
  本来空着 14.4 单位（637 宽下约 24px），不移动就留一条白条，移 30 是连出血 6px 一起算的。
  底部衔接：viewBox 高度从 436 收到 423.4（内容底 420.1 + 描边 3），拉满后塔底与页底出血衔接、
  不再留纸条。文字不另设类，样式只剩 `.cv-coil`，在 `theme.css` 的「5 式整页通栏盘绕塔」段。
- 七块沿丝带走向：顶部横带 191×74 → 转角小三角 87×53 → 右侧竖带 138×111 →
  **最大的一块 L 形 241×146**（横带接竖带，是整条的主力）→ 左下竖块 167×164 →
  右下横块 196×148 → 右下角小三角 118×108。
  七块的 `path` 与 bbox 原样抄自 `components.md` 第八节，改一处要两边同步。
- **每块 `<image>` 铺满自己的 bbox** 并加 `preserveAspectRatio="xMidYMid slice"`，
  于是七块各自独立取景；若整张图铺满 430×485 再裁，每块只剩一条缝。
- **白缝靠描边**：所有 `<image>` 画完后，用同一批 path 再画一层
  `fill="none" stroke="#FFFDF6" stroke-width="2.2" stroke-linejoin="round"`。
  CSS 的 `clip-path` 描不了边，逐块内缩又得手工算偏移——这是十一式里唯一用 SVG 的一式，
  不是风格选择，是几何决定的。
- `viewBox` 让它随列宽自动缩放：改尺寸只改塔宽，七条 path 一位不用动
  （2 / 3 / 4 的 path 是像素写死的，改画布宽要重算）。viewBox 取 `-3 -3 386 423.4`，
  外扩的 3px 是留给轮廓描边的——改成 `0 0 380 420` 会把最外圈的白描边裁掉（2026-11-27 从 436 收到 423.4，让塔底贴到页底）。
- 坑：**七块大小差五倍**。最小的两块（87×53、118×108）只够放「一块色」，
  配图时让它们与相邻块共用同一张，读成「一条带子上的两个连续面」；
  别指望小块单独表意，也别把唯一的证据图塞进小块。
- 坑：横图进竖块照样裁得狠，但这里最深的块只有 164，比 4 的 420 温和，
  四张横图够用；图数不够就相邻重复，不要为了凑数换成竖图。
- 坑：**缝要跟着塔宽放大**。同一份 `stroke-width` 在 430 宽上是 2.4px（正好），
  到 637 宽还是 2.2 就只剩一条刻痕——满幅用 6（显 10px）。但别过 8，
  七块会散成七张贴纸，带子的连续感就没了。
- 坑（内容页）：塔高 485 是**故意不铺满**的，从 150 排到 635、距页脚 40px。
  **430 是内容页的上限**：塔宽 453 时高 512、正好顶到 `.sb` 底边（662），与页脚只剩 13px。
  左列必须有导语 + 标题 + 两条正文才压得住，否则整页右重左轻。
- 坑（通栏）：塔拉满一页高后 `.sb` 只剩左半，**宽度必须限到约 520px**，否则导语会跑进塔后面；
  塔 637 宽 + 左列 520 + 页边距 92，1280 正好放得下，别再加宽塔。
- 坑：`2.2px` 与 `6` 都是 386 宽 viewBox 里的值，随塔宽等比缩放后才是屏幕像素。
- **立体感靠逐段投影 + 交替受光**（2026-11-27 改）：每段挂 SVG 原生滤镜 `#coilShadow`
  （feDropShadow，dy 4 / blur 3，用户单位），后画的段压前面的段，带子读出层叠；
  `.lit` 层按段交替铺 `coilLiteA`（上亮下暗）/ `coilLiteB`（反向）渐变。
  只留塔级一层投影是平的。**投影别用 CSS `filter` 挂内层 `<g>`**——Chrome 会先按
  用户单位栅格化再放大，整塔发虚；SVG 原生滤镜是矢量级渲染，不发虚。

### 6 半圆扇面式

> 多张图片围绕半圆展开，呈扇形放射状布局。


**扇骨就是接缝：四片各画「从圆心拉出的三角形」，外弧与内弧由舞台同一条 path 统一裁出。**

- 几何锁死：圆心在舞台下方 1039.5px，外弧顶点 y=0、半张角 38°、扇面径向厚 290，舞台 1280×449。
- **缝按角度让**：每片两端各让 0.08°（外弧 2.9px、内弧 2.1px）。不能改成固定 px 边距——
  固定值在圆心收拢处会张成锥形大缝，扇骨当场读断。
- 每张图宽 460、按本片中径居中（`--cx`）：每张只裁到自己那格附近，主体不会被邻片抢走；
  按整幅 1280 摆会把竖图压成一条横切片。
- **标题贴条 `.sec-cap` 必须挂在 `.sec-wrap` 里**：扇面是裁剪区，写进 `.w-sec` 会被整块裁掉
  （与 7 同一条坑）。
- 坑：接缝必须放射。竖直等宽缝 + 外轮廓起伏，读出来仍是「拱门」，不是扇子。
- 换张数 / 张角用 `scripts/fan-wall.py` 重算 path、四组三角形与 `--cx`，别手改 path。

### 7 弧形切幅式

> 通过弧形裁切形成横向视觉延伸，突出图片主体。


**只弯上缘，下缘齐平贴内容区底；上缘自左向右单向抬起（左端最低 200、右端最高 44）。**

- 单段三次贝塞尔：`M0 200 C420 196 900 150 1280 44 L1280 440 L0 440 Z`。
  别拼两段——两段切向难接，投影放大后接缝会露折角。
- 方向判据：**上缘是否真的左低右高单向抬起**。做成「两端等高、中央下压」就成下弯飘带，
  与参考走向正好相反（这是这一式最常犯的错）。
- 舞台 440 高，左厚 240、右厚 396；左三分之一的弧几乎不动，正好让出三角纸面放文字块
  `.crest-head`（挂墙外，`left:0; top:0; width:660`）。
- 文字块必须挂在墙**外面**：`clip-path` 会把墙内所有子元素一起裁掉，写在墙里标题整行消失。
- 贴底靠 `.crest-wrap { margin-top:auto }`，投影只向上打（`drop-shadow(0 -12px …)`）。

### 8 矩阵网格式

> 多张图片按照规则网格排列，强调整体性与秩序感。


**2×2 网格，两翼绕中缝各转 22°，整面朝观众卷进来。**

- 三件套：`perspective` 挂容器（1100px）、每列 `rotateY`、沿 Z 退到圆弧上。
  只转不退，边列四角会翘到邻格上；只退不转，边列只是变小、不变形。
- **轴在中缝不在格心**：奇数格 `transform-origin:100% 50%`、偶数格 `0% 50%`，
  两列绕同一条竖轴各转 22°——中缝纹丝不动、两翼向后张。轴放格心就成了两块各歪各的板，
  中缝裂成白沟（实测端列比中缝矮 17%）。
- **立体感的大头是光**：中缝退得最远也压得最暗、两端外沿最亮，再补顶亮底暗与贴地椭圆影。
- 坑：**`.w-cyl` 容器禁止 `filter`**——会把 3D 子层压平，透视直接失效且无报错；
  投影一律改用伪元素（`::before`）。
- 格子必须横（≈638×200）：竖格转动只表现为变窄，看不出卷。

### 9 折页长卷式

> 图片以连续折页方式展开，形成空间层次与立体感。


**四片共边梯形折成一道弧，接缝处上下边严丝合缝。**

- **不用 `rotateY`**：逐片旋转会让相邻两片的公共边错位 3–8px，读成「四张歪卡」。
  做法是把五条折线的上下端点定成同一组数（上缘 66→19→6→19→66、下缘 316→385→398→385→316），
  相邻两片共用同一对端点，梯形裁切自然拼成一条连续折线。
- 片宽不等：两端各 316px、中间两片 `1fr`——等宽读成四块等大的板，没有「转过去」的意思。
  `gap:0`，折缝 = 每片左端 3px 高光 + 右端 6% 宽暗边；`background:none`（否则裁剪区外露白带）。
- **片间亮度差必须有**：相邻两片朝相反方向转，不压暗就读成一整张连续全景图
  （端片 `brightness:.84`、中片 `1.04`）。
- 高度 404；再高会压图注，每加 20px 先量 `.sb`。

### 10 弧幕连屏式 / 11 内弧

> 多张竖幅图片沿弧线连续排列，形成环幕视觉效果（10 外弧；11 加 `.sag`，中段鼓起、两端收进）。


- 与 9 同法：四片共边裁切，相邻两片共用同一对折线端点。
  **端点错 1% 就是 4px 台阶**（上缘 6 / 12.5 / 14.5 / 12.5 / 6、下缘 94 / 87.5 / 85.5 / 87.5 / 94，
  上下各留 6px 别顶到 404 的边界）。
- 缝靠每片左右各裁 3px 让出，**不能用 `gap`**——gap 会把梯形接缝撕开。
- 端片上下都放大、中片压短，带子才有透视；两端比中段高 13%，再多就成锯齿。
- 受光写在每片自己的渐变里：外端离观众近、更亮；中段退远、压暗。
  整条带子压一层统一明暗，弯的地方就没有明暗交界了。
- 五张加 `.n5`（缝更密，端的放大与中段的压缩各让一步，否则端张被挤成细条）；
  内弧加 `.sag`，参数逐条翻转。

### 十一式通用规则

1. **图数**：1 取 4–5、2 取 4、3 取 8、4 取 4–5、5 取 7 块（5–7 张图，不够就相邻重复）、6 取 4 片、7 取 4 张、8 取 4 格（2×2）、9 取 4 片、10 / 11 取 4–5 片。三张以下走双栏 / 三栏卡片；十张以上拆页，或改用 `.tbl` 索引加两张代表图。
2. **等权**：所有图等宽等高、缝 3px 白纸色，外轮廓只由容器遮罩决定（4 也不再逐张改高度），
   不加各自的圆角、边框。
3. **允许 `cover` 的唯一场景**：同题材并置、单张不承担唯一证据。人物面部、图内文字、关键细节
   必须落在居中 60% 安全区，逐张在缩略图上确认。整套 deck 里唯一的那张证据图仍然 `contain` + 浅色底。
4. **立体只许用纸的材质**：暖白 `#FFFDF6` 拼缝、暖褐 `rgba(74,58,34,…)` 投影、
   顶亮底暗的极窄渐变。禁发光、禁玻璃、禁彩色阴影、禁内发光、禁多重描边。
5. **一条文字带**：标题 + 一条图注（15–17px），不逐图配长说明。要点名某张时用与图注对应的
   ①②③ 编号，不把标签压在图面上。
6. **素材同质**：同一次拍摄或同一模型出图，色温接近；横竖混排会破坏接缝，进场前统一裁成同一比例。
7. **节奏**：一套 deck 里图墙最多出现两次，且形状不同；不与图文分栏页相邻，否则连看两页都是“图 + 字”。
8. **入场动画**：`theme.css` 已内置 0.7s 的浮起与转正（`.w-wave` / `.w-fan` / `.w-coil` / `.w-sec` / `.w-crest` / `.w-fold` 上浮，
   `.w-depth` 从更深处转正，`.w-fan img` / `.w-sec .sd img` / `.w-cyl .cc` / `.w-arc .ai` 逐张淡入），随 `.slide.on` 触发，
   且只在 `prefers-reduced-motion: no-preference` 下生效。
   要换成 GSAP 编排就引入 `assets/fx.js`，它会自动让 CSS 入场退位；引入后仍须满足下一节的五条底线。

### 技术选型与增强层（可选）

**HTML 是交付载体，不是能力上限。** 一套 deck 的底线是「双击能开、断网能放、打印能出、文字可选」，
在这个前提下用 CSS、GSAP 还是 WebGL，按效果择优，不预设禁令。
判断顺序三步，不跳步：

1. **静态是否正确**——把 JS 全关掉，版面还立得住吗？立不住先修静态，别拿动画盖住问题。
2. **原生能不能做到**——下表第一列能覆盖，就不引入依赖。
3. **值不值得**——只有「原生明显吃亏 + 效果确实服务内容」才升级；装饰性动效不配付这个代价。

| 要达到的效果 | 首选 | 什么时候该升级 |
|---|---|---|
| 曲线裁切、斜边、弧裙 | `clip-path:path()` | 需要多段布尔运算 → SVG `<mask>` |
| 多块共享轮廓、还要描出拼缝 | 内联 SVG + `<image>` + `clipPath` | —（5 式就是这么做的） |
| 近大远小纵深 | `perspective + rotateY` | GSAP 不额外加分，仍是同一个矩阵 |
| 高度错落、扇形 | `flex + height` | — |
| 沿轮廓投影 | `filter:drop-shadow()` | 数百张图的场景才轮到 shadow map |
| 入场浮起、逐张淡入 | CSS `@keyframes` | 元素 > 6、需要暂停 / 回放 / 错峰序列 → GSAP 时间轴 |
| 路径运动、物理回弹、滚动联动 | GSAP（`stagger` / `MotionPathPlugin` / 自写 rAF） | — |
| 整条图墙真实起伏、顶点位移、液体 | WebGL（Three.js 或原生 WebGL，平面 + 顶点着色器） | CSS 只能整块遮罩，做不了单像素位移 |
| 图像网格 warp、置换、故障 | WebGL + 置换贴图 | 数据量小时 Canvas2D 逐像素更省 |
| 大量粒子、逐帧绘制 | Canvas2D / WebGL | — |

**接入方式已内置：`assets/fx.js`（零依赖，可选）。**

```html
<!-- 引入顺序：gsap（可选，放 assets/vendor/）→ fx.js → deck.js -->
<script src="assets/vendor/gsap.min.js"></script>
<script src="assets/fx.js"></script>
<script src="deck.js"></script>
```

`gsap.min.js` 不建议进仓库：`npm i gsap` 后把 `node_modules/gsap/dist/gsap.min.js` 拷进项目
`assets/vendor/` 即可（约 70KB），随项目一起分发，断网也能放。

- 没检测到 `gsap`：`fx.js` 直接退出，`theme.css` 的 CSS 入场照常生效，页面不多一个字节的依赖。
- 检测到 `gsap`：加 `html.fx-js`，CSS 入场让位，改由时间轴编排（图墙浮起、扇形逐张、纵深转正）。
- 自定义效果用 `data-fx` 声明 + `RP.fx.register` 注册，**返回值是清理函数**，离页自动销毁：

```html
<div class="w-wave" data-fx="wave-gl"><img src="assets/b1.jpg" alt="">…</div>
```

```js
// 只有确实需要单张图独立起伏时才上 WebGL；否则原来的 clip-path 就够
RP.fx.register('wave-gl', function (el, api) {
  const canvas = document.createElement('canvas');
  const gl = canvas.getContext('webgl');           // 上下文由本配方持有
  el.appendChild(canvas);
  let raf = requestAnimationFrame(function loop(t) { /* 顶点位移 + 绘制 */ raf = requestAnimationFrame(loop); });
  return function () {                             // 离页：停帧、删上下文、清引用
    cancelAnimationFrame(raf);
    gl.getExtension('WEBGL_lose_context') && gl.getExtension('WEBGL_lose_context').loseContext();
    canvas.remove();
  };
});
```

**五条底线（约束交付物，不约束技术选型）：**

1. **静态回退**：JS 未执行 / 依赖 404 时版面已经正确。增强层只叠加运动，不许改尺寸与位置。
2. **依赖本地化**：GSAP 等放 `assets/vendor/` 或内联；CDN 只是可选回退，不能是唯一来源。
3. **三种场景回终态**：`@media print`（已全局停动画）、截图模式 `?shot`（`fx.js` 直接不播）、
   `prefers-reduced-motion`（不接管）。终态必须等于静态 CSS 的样子。
4. **文字不进 canvas**——唯一硬约束。标题、正文、图注永远留在 DOM 里：
   canvas 里的字不可选、不可搜、不可无障碍读，打印还会糊。
5. **性能预算**：一页最多一个 WebGL 上下文，纹理 ≤ 2048px，离页必须销毁；
   首帧 200ms 内可交互，动效不得挡住翻页键。

**不要做的三件事**：为了炫技加动效；用动画掩盖版式毛病；把 CDN 当唯一依赖来源。

### 四式可选增强

静态版式已经把形态做对，动效只加「叙事」。以下都属可选，不加也成立：

- **2 波浪带**：GSAP 给 `clip-path` 做轻微位移动画即可伪造流动（比 WebGL 轻一个数量级）；
  只有要「每张图各自起伏」时才上 WebGL 顶点位移。
- **3 纵深墙**：逐列 stagger + 轻微 `y` 视差，比整块转正更像「插进纸里」；
  注意 `transformPerspective` 要跟着写，否则 `rotateY` 丢透视。
- **4 扇形**：五张依次落位、末尾一点回弹，节奏对上讲解的「一张、一张」。
- **1 照片卡**：四张错峰落下，落定后不再漂浮——持续漂浮会读成「没摆稳」。

## 页面空旷 / 拥挤的现场判断

| 症状 | 真实原因 | 处理 |
|---|---|---|
| 下半页空 150px+ | 只用了一行 flex 内容 | 补 `.bar` 或把一个模块改成 `.grow` 撑满 |
| 卡片很大但字很少 | 为等高而拉高 | 去掉 `align-items:stretch`，或把卡片改成表 |
| 文末贴底、页脚被压 | 忘了 `.sb > *:not(.grow)` 的 `flex-shrink:0` | 已经默认开启，改为精简内容 |
| 图片两侧大片留白 | 容器比例与原图不符 | 竖图给高度、横图给宽度，按原图比例反算容器 |
| 引导语出现孤字行 | `max-width` 或右侧标签挤占 | 扣减 `max-width` 或精简文案 |
| 大字块浮在中间 | `justify-content:center` 用在整页 | 只在“单块内容对着高图”时用，且左右要等高 |

## 一次改多页时的顺序

1. 先改 `:root` token（字号、间距）——一次生效全篇。
2. 再改页面骨架类（`.sh`/`.sb`/`.foot`）——影响所有页。
3. 最后逐页处理特例，**每改 3–5 页跑一次 `audit.js`**，不要攒到最后。
4. 单页反复试错时用 `node scripts/audit.js <url> --no-shots` 只拿数字，快得多。
